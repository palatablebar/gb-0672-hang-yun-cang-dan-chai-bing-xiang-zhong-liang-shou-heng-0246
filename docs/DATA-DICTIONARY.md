# 舱单数据定义

id是主单、分组单或箱货明细唯一字符串编号，parent为空表示主单。节点申报件数、净重和毛重是其完整子树的申报总量，校验时只加直接子节点，避免多层重复计数。包装carton=1件，pallet=10件；重量kg与t统一为kg。件数必须非负整数，净重非负且毛重不得低于净重。
拆并结构采用每节点最多一个父级的有向图；自环、长环、缺父级均阻断封存，保留环路径。不会以平面求和替代逐层校验。
危险品按明确分类与UN编号检查，3类与5.1类禁止同箱；未知分类和缺失编号需复核。此演示规则只覆盖文中三类，不替代运输合规审批。
报关总量只汇总主单，与context.json内的申报件数、净重和毛重逐项比较。重复同值折叠，重复编号冲突全部隔离。原始计数=采纳+隔离+空行+重复表头+重复同值行。
封存需所有图、重量、危险品和采信问题处理完毕。数值均Decimal，对外字符串保留精度，编号不转整数。

## 放行清单（M8 跨航次分批出运）

主提单可跨多个航次分批出运，整节点出运：一条出运行选中节点即覆盖该节点整棵子树，子树内所有节点未出运余额归零；未被覆盖的节点余额=自身申报量−祖先出运行已出运量，余额随当前有效舱单自底向上重新核验。

- 父层和子层在同一航次只计一次：选中节点若有选中的祖先，子层以 LINE_COLLAPSED 折叠并阻断本次交接，清单只保留父层。
- 放行行的件数、净重、毛重直接取逐层核验后的节点值；节点存在 WEIGHT_NOT_BALANCED、DEPENDENCY_CYCLE、MISSING_PARENT 或未出运余额不足（INSUFFICIENT_BALANCE）时写明阻断原因并停止交接，不产生放行行。
- 修订裁决逐主单进行：已出运节点缺失（SHIPPED_NODE_MISSING）、证据数值被改写（SHIPPED_EVIDENCE_CHANGED）、关系或重量出错则冻结该主单（MASTER_FROZEN）；修订只触及未出运明细时主单保持可放行，剩余余额按新舱单重算。
- 出运申请以 request_id 幂等：同一申请重试只回显首次结论（replayed=true），attempt_no 不增加；确认失败时失败记录留痕但不产生生效行，旧版出运结果与原清单保留。修订舱单经 baseline_run_id 引用旧批已出运证据。
- ship_requests 表持久化申请时间线（request_id、run_id、attempt_no、voyage、payload、created_at）；confirmed_lines 只汇总状态为放行的申请。归档包 release.json 含生效行与全部申请记录。
